Como funciona

EXEMPLO: "o teste de login está falhando, corrija"

1 · Contexto

Lê o pedido, as regras do projeto e os arquivos relevantes.

2 · Pensar

"Preciso ver o erro. Vou rodar o teste."

3 · Agir

Chama a ferramenta npm test -- login.

4 · Observar

"Esperado 423, recebido 401." Volta para o passo 2 com essa informação.

Na prática

Um agente inteiro cabe em 15 linhas

Código
agente_minimo.py · pseudocódigo em Python
ferramentas = {"ler_arquivo": ler_arquivo, "rodar_testes": rodar_testes,
               "editar_arquivo": editar_arquivo}

def agente(objetivo, max_passos=20):
    historico = [{"role": "user", "content": objetivo}]
    for passo in range(max_passos):
        resposta = llm(historico, tools=ferramentas)        # 1. pensar
        if not resposta.chamadas:                           # nada a fazer?
            return resposta.texto                           #    terminou
        for chamada in resposta.chamadas:                   # 2. agir
            funcao = ferramentas[chamada.nome]
            resultado = funcao(**chamada.argumentos)
            historico.append({"role": "tool",               # 3. observar
                              "content": resultado})

    return "Parei: atingi o limite de passos."              # 4. freio

02
O harness do agente

Mesmo modelo, harness diferente: agente diferente.

min 18 → 31
Conceito

O modelo é o motor. O harness é o carro inteiro.

Anatomia

Harness é todo o software em volta do LLM: monta o contexto, oferece ferramentas, aplica permissões, guarda memória e registra o que aconteceu.

Um motor potente sem freio e sem volante não é um carro. É um risco.

Avance para montar as camadas.

O harness em pseudocódigo

Código
def montar_contexto(historico):
    return [prompt_do_sistema,
            ler("CLAUDE.md"),                  # regras do projeto
            metadados_das_skills(),            # só nome + descrição
            *compactar(historico)]             # resume se ficar grande


def executar(chamada):
    regra = permissoes.avaliar(chamada)       # allow / deny / ask
    if regra == "deny":  return "negado pela política"
    if regra == "ask" and not humano_aprova(chamada):
        return "usuário recusou"
    for hook in hooks["PreToolUse"]:
        if hook(chamada) == "bloquear": return "bloqueado por hook"
    with sandbox(rede=False, pasta="./projeto"):
        resultado = rodar(chamada)
    telemetria.registrar(chamada, resultado,
                         tokens=uso.tokens, custo=uso.custo)
    return resultado

Na prática

Permissões e hooks: os freios configuráveis

Configuração
.claude/settings.json
{
  "permissions": {
    "allow": ["Bash(npm run test:*)",
              "Read(src/**)"],
    "deny":  ["Read(.env)",
              "Bash(rm -rf:*)",
              "Bash(git push:*)"]
  },
  "hooks": {
    "PreToolUse": [{
      "matcher": "Bash",
      "hooks": [{
        "type": "command",
        "command": "python .claude/guarda.py"
      }]
    }]
  }
}
.claude/guarda.py · hook que roda antes de todo comando
import json, sys, re

pedido = json.load(sys.stdin)              # o harness envia a chamada
comando = pedido["tool_input"].get("command", "")

PERIGOSOS = [r"rm\s+-rf\s+/", r"curl .*\|\s*sh",
             r"DROP\s+TABLE"]
for padrao in PERIGOSOS:
    if re.search(padrao, comando, re.I):
        print(f"Bloqueado: {padrao}", file=sys.stderr)
        sys.exit(2)                        # código 2 = bloquear

sys.exit(0)                                # 0 = pode seguir
Regra fixa para o simples, código para o esperto. Os dois vão para o Git.

Tokens, local × nuvem, CAPEX × OPEX

Agente não é grátis. Quem entende a conta toma decisões melhores.

min 31 → 48
Conceito

Token: a unidade de leitura e de cobrança

Interativo

O modelo não lê letras nem palavras. Lê pedaços de texto. Você paga por pedaço lido (entrada) e por pedaço escrito (saída).

caracteres0
tokens ≈0
car./token0

Aproximação didática. Cada modelo tem o próprio tokenizador; textos em português e código costumam gerar mais tokens por palavra do que inglês.

Como funciona

A cada volta do loop, o agente relê tudo

Interativo

O modelo não tem memória entre chamadas. A cada passo, o harness reenvia todo o histórico. O custo cresce muito mais rápido que o número de passos.

tokens de entrada0
equivalente cobrado0

Contexto inicial de 15 mil tokens (sistema + regras + arquivos). Com cache, o trecho repetido custa ~10% do preço normal (valor de exemplo; varia por fornecedor).

Na prática

Seis alavancas para gastar menos tokens

Checklist
Contexto enxuto

Aponte os arquivos certos. "Leia o repositório inteiro" é a forma mais cara de começar.

Prompt caching

Prefixo estável (sistema, regras, arquivos) no começo da mensagem, para ser reaproveitado.

Divulgação progressiva

Skills e documentação carregadas sob demanda, não tudo de uma vez.

Modelo certo por tarefa

Modelo pequeno para renomear variável; modelo grande para arquitetura.

Sessões curtas

Uma tarefa por sessão. Ao terminar, comece outra limpa ou compacte o histórico.

Saídas curtas

Saída custa várias vezes mais que entrada. Peça diffs e respostas objetivas.

Uma spec bem escrita é a maior economia: o agente erra menos e precisa de menos voltas.

Roteamento híbrido: cada tarefa no modelo certo

def escolher_modelo(tarefa):
    if tarefa.tem_dado_sensivel: return "local"

    if tarefa.tipo in {"autocomplete", "lint", "commit"}:
        return "local"

    if tarefa.arquivos > 5 or tarefa.tipo == "arquitetura":
        return "fronteira"

    return "nuvem-rapido"

Conceito

CAPEX × OPEX: comprar o carro ou chamar um app?

Finanças
CAPEX · despesa de capital
Comprar GPUs e servidores
  • paga tudo antes de usar
  • hardware deprecia; em IA, envelhece rápido
  • custo previsível depois da compra
  • exige gente para operar
OPEX · despesa operacional
Pagar API por token
  • começa hoje, sem investimento
  • escala junto com o uso
  • fatura variável, cresce com o sucesso
  • sempre o modelo mais novo
Startup no início

OPEX. Caixa curto e demanda incerta: não imobilize dinheiro.

Empresa com uso alto e estável

Avaliar CAPEX para a carga previsível; API para os picos.

Dados regulados ou sem internet

Local, mesmo que custe mais. Exigência legal não entra na planilha de preço.

Os quatro artefatos de uma feature

Exemplo navegável
# Spec 012 · Bloqueio de login

## História
Como aluno, quero que minha conta seja protegida
contra tentativas repetidas de senha.

## Requisitos
RF-01 Após 5 falhas em 15 min, bloquear a conta por 15 min.
RF-02 Mensagem genérica: não revelar se o e-mail existe.

## Critérios de aceite
DADO 4 falhas      QUANDO ocorre a 5ª   ENTÃO responde 423
DADO conta bloqueada QUANDO passam 15 min ENTÃO login volta

## Fora do escopo
Captcha, autenticação em dois fatores.
# Plano · Spec 012

## Arquitetura
- Tabela `login_attempts(user_id, ts, ok)`
- `AuthService.registrar_falha()` e `.esta_bloqueado()`

## Contrato
POST /login
  200 → token
  401 → "E-mail ou senha inválidos"   (RF-02)
  423 → "Conta temporariamente bloqueada"

## Decisões
- Janela deslizante de 15 min (não contador fixo)
- Sem Redis por enquanto: volume baixo, PostgreSQL basta
# Tarefas · Spec 012

- [ ] T-001 Migração da tabela login_attempts
- [ ] T-002 Testes de aceite (devem FALHAR agora)  [P]
- [ ] T-003 AuthService.registrar_falha            [P]
- [ ] T-004 AuthService.esta_bloqueado + janela
- [ ] T-005 Rota /login devolve 423
- [ ] T-006 Mensagem genérica no 401 (RF-02)

[P] = pode rodar em paralelo com a anterior
## PR #87 · Bloqueio após 5 falhas

Spec: specs/012-login/spec.md
Tarefas: T-001 … T-006

### Critérios de aceite
- [x] 5ª falha responde 423      test_bloqueio.py::test_quinta
- [x] libera após 15 min         test_bloqueio.py::test_janela
- [x] 401 não revela e-mail      test_login.py::test_generico

### Revisão
- Revisor humano: arquitetura e segurança
- Agente revisor: 0 desvios da spec

Na prática

O pipeline em GitHub Actions

Código
name: ci-agentico
on: pull_request

jobs:
  testes:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - run: npm ci && npm test -- --coverage
  spec-gate:
    needs: testes
    runs-on: ubuntu-latest
    steps:
      - name: O PR cita uma spec?
        env:
          CORPO: ${{ github.event.pull_request.body }}
        run: |
          echo "$CORPO" | grep -qE "Spec: specs/[0-9]+" \
            || (echo "PR sem spec vinculada" && exit 1)
  revisao-agente:
    needs: spec-gate
    runs-on: ubuntu-latest
    steps:
      - uses: anthropics/claude-code-action@v1
        with:
          anthropic_api_key: ${{ secrets.ANTHROPIC_API_KEY }}
          prompt: "Revise este PR contra specs/ e comente desvios."

Armadilha clássica

Colar ${{ ...body }} direto num run: deixa qualquer pessoa que abre um PR executar comandos no seu CI. Use env:.

AI safety

Defesa em camadas: nenhuma barreira é perfeita sozinha

Modelo do queijo suíço
Ameaças
  • prompt injection em arquivos e páginas
  • vazamento de segredos e dados
  • comando destrutivo: apagar, forçar push
  • pacote alucinado: nome inventado registrado por atacante (slopsquatting)
Um buraco numa camada é coberto pela seguinte. Por isso o harness e o processo importam tanto quanto o modelo.
